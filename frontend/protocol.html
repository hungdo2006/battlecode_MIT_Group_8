Giao thức bot

Robot Battle và OTT v2 nhận một file Python/C++/Java không rỗng, tối đa 256 KiB. Java dùng public class Main, không package. Đọc một dòng JSON UTF-8 trên stdin, trả một JSON action trên stdout rồi flush; debug vào stderr.

Robot Battle

Observation có player, turn, rules, you, enemy; robot có x/y/hp. Cả hai bot nhận cùng trạng thái trước lượt; x sang phải, y xuống dưới. Move bốn hướng; attack trúng ô kề theo khoảng cách Manhattan sau move.

{"type":"move","direction":"right"}
{"type":"attack"}
{"type":"wait"}

OTT v2

Chỉ bot tới lượt được gọi. Board 9×9, row 0 ở dưới, col 0 bên trái; ô null hoặc {"id":"...","owner":"A","type":"rock"}. Type là rock/paper/scissors. A nhắm (8,8), B nhắm (0,0). Chọn từ legal_actions để có nước hợp lệ; server vẫn kiểm tra lại.

{"action":"move","from":{"row":1,"col":3},"to":{"row":2,"col":4}}

Di chuyển một ô theo tám hướng; Búa ăn Kéo, Kéo ăn Bao, Bao ăn Búa. Không có wait/attack riêng. Đến đích hoặc loại hết một loại quân địch thắng ván; hết giới hạn nước/không còn nước hợp lệ hòa ván. Xem rules, round và scores để theo dõi trận nhiều ván.

Giới hạn Robot/OTT

Giữ một process mỗi bot qua các ván. Phản hồi đầu: 3 giây; sau đó: 1 giây. Stdout tối đa 4 KiB/dòng, 256 KiB/trận; stderr 64 KiB/trận. Crash, timeout hoặc action sai là lỗi bot; lỗi hạ tầng gây gián đoạn và không tự tính bot thua.

Docker Compose mặc định dùng sandbox container; native runner là subprocess và chỉ dành cho code tin cậy.
